## 它解决什么问题

从 ERP、拼多多商家后台、淘宝、1688、金蝶、用友导出的表格，90% 会在这些地方出问题：

| 症状 | 后果 |
|---|---|
| `1,250` 里的逗号没加引号 | 导入时整行**右移一列**，后面所有字段全错位 |
| 全角数字 `１２５０`、全角字母 `ＡＢＣ` | 排序错乱、VLOOKUP 匹配不上、按数量筛选漏数据 |
| `￥1,200.50` / `1200元` | Excel 认成文本，求和为 0 |
| 日期混着 `2026/3/5`、`2026-03-06`、`2026年3月7日` | 无法排序、无法按月汇总 |
| 规格写成 `M8*30`、`M8×30`、`M8 x 30` | 同一货品被当成三种，去重和比价都失效 |
| 单位混着 箱/盒/个 | 求和出来的数字没有意义 |

这些错误**不会报错**，只会安静地让你算错。

## 它怎么做

14 条规则，每条异常都给出**规则编号 + 一句人话依据**。关键是分成三档，不混在一起：

- **已自动修复** —— 确定性的、可逆的、不改变数值含义的改动（去空格、全角转半角、去千分位、统一日期与乘号）
- **建议核对** —— 只是提醒，**不改你的值**（完全重复行、同规格两个名字）
- **需你决定** —— 机器不猜（`1,25` 到底是 1.25 还是 125？空着的单价该填什么？）

> 第三档是这个工具存在的理由。市面上大部分"一键清洗"会把 `1,25` 默默改成 `125`，然后你拿着一个错了 100 倍的表去做决策，而且**永远不知道**。

## 规则表

| 编号 | 规则 | 档位 |
|---|---|---|
| R001 | 全角数字/字母/标点转半角 | 自动 |
| R002 | 千分位逗号与货币符号清理（¥ ￥ $ € £ 元 圆 RMB CNY） | 自动 |
| R003 | 首尾空白、全角空格、零宽字符 | 自动 |
| R004 | **小数逗号歧义**（`1,25` 可能是 1.25 或 125） | 待决定 |
| R005 | 规格乘号统一为 `x`（只在数字之间才算乘号） | 自动 |
| R006 | 完全重复行 | 建议 |
| R007 | 整行为空 | 自动 |
| R008 | 必填列出现空值（该列填充率 >80% 时） | 待决定 |
| R009 | 同一列内单位不统一 | 待决定 |
| R010 | 同规格同单位、却是两个名字 | 待决定 |
| R011 | 日期格式统一为 YYYY-MM-DD | 自动 |
| R012 | 数字列里混入文字 | 待决定 |
| R013 | **行内列数与表头不符**（未加引号的逗号导致） | 待决定 |

## 用它需要几步

1. 从 Excel 里「另存为 → CSV UTF-8」，或直接拖已有的 CSV
2. 拖进页面（UTF-8 / GBK 自动识别，中文不乱码）
3. 看异常清单，处理「需你决定」的那几条
4. 下载清洗后的 CSV + 异常清单 CSV（可以留档、可以给同事看）

**为什么不能直接读 .xlsx**：那需要把整个解析库塞进页面，体积翻十倍。换来的是「双击即用、完全离线」，这个取舍我认为值得。如果你更需要直接读 xlsx，告诉我。

## 已知边界（不装懂）

- 不做**语义判断**：不知道「六角螺栓 M8x30」和「六角螺母 M8x30」是不是一个东西，所以不会替你去重
- 不做**单位换算**：箱、卷、包之间没有确定的换算关系，只有你才知道一箱装几个
- 不处理**多表关联**：只清一张表
- 没有 OCR：图片里的表格读不了
- 大文件在 5 万行以内流畅；再大会卡（纯浏览器内存限制）

## English

A single-file, fully offline CSV cleaner for messy Chinese business exports (GBK, full-width characters, `￥`, thousands separators, mixed date formats, misaligned rows).

Three-tier output: **auto-fixed** / **suggested** / **needs-your-decision**. The third tier is the point — `1,25` is *not* silently rewritten to `125`, because that could be off by 100×.

No dependencies. Open `index.html`. MIT licensed.
